# Synthetic contract examples

These are independent record-shape examples for development, not a collected case, diagnosis
or authorized rule change. The intent confirmation is deliberately false. The standalone
proposal example illustrates a schema and is not eligible output from the analysis example.
No example executable is launched or peer contacted. Runnable diagnostic bundles and reports
will be added only when the engine and storage implementation can produce and verify them.
# Exercised synthetic engine example

synthetic-case contains invented host, policy, network and event data with real matching hashes.
expected-analysis.json is produced by the shared pure engine. intent-synthetic-confirmed.json
uses a true identity flag solely as synthetic scenario ground truth; it is not authorization for
an actual computer or flow. The default intent.json remains unconfirmed. sample-report.html is
a share derivative with random aliases and no raw free text. No case comes from a real endpoint.

The contract walkthrough verifies bundle loading, exact engine facts, a nonexecuting proposal
and static report rendering. CLI and native collection integration are still pending. Native
policy continuity, path/direction mapping and real diagnosis are not validated by these fixtures.
