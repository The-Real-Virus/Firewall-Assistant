# Optional-source failures and truncation

Master Part B6 states that truncation always makes completeness incomplete. P07 also requires
an unavailable optional text log to preserve useful required-source findings. Apply both rules:
an inaccessible optional source remains explicitly unavailable without failing otherwise complete
required evidence; actual truncation, including an unterminated optional log, makes analysis
incomplete with exit5. Valid Security-event findings remain visible, and no proposal is permitted
from an incomplete result. A malformed intact optional record is an optional error with provenance.

Manifest/analysis models reject a complete claim with a truncated source. Parsed text provenance
can downgrade the analysis while leaving the original captured manifest unchanged. Source counts
are checked against accepted text observations and mismatches are explicit errors. Text records
never supply application identity or an inferred local-to-UTC conversion.

This resolves the generic/specific wording conservatively; it adds no new approval or external
access. Native captures and privacy validation remain blocked until actual evidence is supplied.
